# 研发计划

北极星：在一块真正的 AI Passport 上，能翻完 151 只、打开每一页资料、听到叫声，同时不破坏小程序 Recovery。

按这个顺序做。前一里程碑验收还是红的，不要跳到后面，文档除外。

## M0 — 项目骨架

- 根目录 README 配对，以及 `docs/assets/pokedex/` 下的文档。
- 可主机测试的翻页：1–151 循环、范围内随机、资料页循环。
- 抓取脚本写出 `assets/pokedex/gen1/catalog.json`。
- 原图和原始叫声加入 `.gitignore`。

验收：`./tools/validate.sh --static` 跑到 `tests/test_pokedex.c`；目录含 151 个编号，且有中文名、属性、能力值、招式、进化字段。

## M1 — 目录质量

- 中文名和介绍来自 PokeAPI `zh-hans`。`WHOAMI_ROOT` 立绘缓存只用于打包精灵图，不进目录文本。
- 招式最多 8 个。进化条件要能在 240 px 面板上读完。
- 由 JSON 生成 `pokedex_catalog.inc`。

验收：主机测试能解析每一条；抽查妙蛙种子、皮卡丘、伊布和一只化石宝可梦。

## M2 — 精灵图

- 151 张图转成 80 × 80 设备精灵。
- 拆开 RGB565 打包，避免单个 SPIFFS 文件超过 `pokedexfs` 大约一半。
- 用手持图鉴外壳画封面页。

验收：记下精灵占用；截图或真机上能认出皮卡丘和喷火龙。

## M3 — 中文界面

- 按目录和界面文案做 16 像素子集字库。
- 封面、介绍、能力、招式、进化页。
- 首页：顺序查看 / 随机查看。开机直接进玩法。

验收：各页中文没有豆腐块；确定键翻页；上下键换编号。

## M4 — 叫声与数据分区

- 下载 legacy OGG，编成 IMA-ADPCM。
- 增加 `pokedexfs`，地址 `0x35A000`，大小 `0x3A6000`。
- 工作任务：封面长按确定播放叫声，然后回首页。

验收：`./tools/validate.sh --firmware` 仍满足 Recovery 契约；真机能播出一声叫声。

## M5 — 真机打磨

- 电量放在红色顶框右上角。
- 随机模式不立刻重复上一只。
- 不会进化、缺叫声时温和降级。
- 给玩法补 changelog。

验收：真机走完 151，或至少录下第一只、中间、最后一只和一次随机跳转。

## V1 发布前不做

按名搜索、后续世代、闪光、属性相克测验、Wi-Fi 更新、捕获 / 已收服标记。
